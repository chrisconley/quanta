# Analysis: Shopify/draggable

- **Repo**: Shopify/draggable (~18.5k stars)
- **Type**: JavaScript drag-and-drop library (`Draggable` plus `Sortable`/`Droppable`/`Swappable` modules and plugins).
- **Length**: ~5 KB. Short; most depth is punted to per-directory READMEs under `src/`.

## Sections

1. **Badge row** — four badges (npm version with custom label `@shopify/draggable`, CI, "PRs Welcome," hardcoded "Bundle size - 16.2kB" in red).
2. **Hero image link** — a usercontent GitHub image anchor pointing at `shopify.github.io/draggable`; no alt text ("").
3. **"Development" heading (an unusual H1)** — used here not as a "how to develop" section but as the slot for the maintenance-status notice.
4. **Maintenance-status notice** — two bolded paragraphs: "Draggable is no longer maintained by its original authors" (passed to "new collaborators," "no longer worked on by anyone at Shopify") and a "We are still looking for more maintainers!" call, with an obfuscated email `max.hoffmann (at) shopify (dot) com` and a vague vetting promise ("You may be asked a few questions before obtaining collaboration permission").
5. **Horizontal rule** separating disclaimer from pitch.
6. **Pitch prose** — one paragraph explaining the `Draggable` core and four companion modules, clarifying that Draggable itself is the plumbing (mirror, events, sensors) and doesn't sort on its own.
7. **Features** — four bullets (native/mouse/touch/force-touch events, event lifecycle hooks, sensor extensibility, "The library is targeted ES6 first").
8. **Table of Contents** — five-link anchor list.
9. **Install** — npm / yarn one-liners plus a long CDN block with seven `<script type="module">` snippets importing from jsdelivr (entire bundle, each of Draggable/Sortable/Droppable/Swappable individually, Plugins namespace, and a UMD browser fallback with `window.Draggable`).
10. **Browser Compatibility** — single-row HTML table with 48x48 browser logo PNGs from `alrra/browser-logos` and "Last 3 versions ✔" for Chrome/Firefox/Opera/Safari/Edge; defers detail to the `browserslist` field in package.json.
11. **Documentation** — nested bulleted index of 20+ source-tree paths (`src/Draggable/DragEvent`, `src/Draggable/Plugins/Mirror/MirrorEvent`, etc.). Each link goes to an in-repo directory rather than a hosted doc site.
12. **TypeScript** — one-sentence note that definitions are included, with a `doc/typescript.md` link.
13. **Running examples** — `yarn && yarn start` one-liner.
14. **Contributing** — two sentences, pointing at CONTRIBUTING.md.
15. **Related resources** — two entries, both the Ember CLI shim by `@timrourke` (once on GitHub, once on NPM — same project listed twice).
16. **Copyright** — single-line Shopify copyright notice.

## Tone & style

- **Register**: Corporate-terse — all signal, no marketing. Reads like internal README boilerplate generated by a Shopify engineering template, with the hand-edited maintenance notice layered on top.
- **Voice**: Impersonal third-person for the pitch ("Draggable abstracts native browser events"); first-person plural only in the maintenance notice ("We are still looking for more maintainers!").
- **Formatting**: Inline badges at the top, a centered `<img>` hero, then level-1/level-2 headings in standard GitHub style. Nested Markdown bullets (not a file tree), HTML table for browser compatibility, seven back-to-back `<script type="module">` blocks for CDN variants.

## Notable conventions

- **Using the "Development" H1 as the slot for the abandonment disclaimer** — visually and structurally misleading (readers expect a "how to contribute/build" section) but preserves the original heading hierarchy; the choice suggests a minimal edit to avoid reflowing the rest of the document.
- **"No longer maintained by its original authors ... no longer worked on by anyone at Shopify"** — the unusual corporate-attribution phrasing explicitly separates the repo namespace (`Shopify/`) from the engineering org, which is how an F500-owned repo detaches without moving the URL.
- **Obfuscated email (`max.hoffmann (at) shopify (dot) com`) for maintainer applications** — a pre-GitHub-Discussions escape hatch that assumes the reader can parse it; also signals a human-gated onboarding rather than "open a PR."
- **Bundle-size badge is a hardcoded red `shields.io/badge/` string ("16.2kB")**, not a dynamic size-limit badge — decorative rather than enforced.
- **Doc index points at `src/`-tree directories**, not a hosted site — each module has its own README, turning the repo itself into the documentation. This is a Shopify-internal convention for JS libraries (mirrors Polaris and others).
- **"Related resources" double-lists the same Ember shim** (GitHub entry + NPM entry) — padding or oversight; either way, it's a weak external-links section where a larger project would have an ecosystem page.
- **No "Getting started" / "first example" code snippet** — the README skips from install to CDN variants to browser-support table without ever showing `new Draggable(...)` in action, pushing readers to the website (hero image link) or to `src/Draggable/README.md`.
- **`shopify.github.io/draggable` hero image has empty alt text (`alt=""`)** — an accessibility miss unusual for a Shopify repo.

## Takeaway pattern

This is the "corporate open-source in sunset mode" archetype: a well-scaffolded F500 README (badges, CI, CDN variants, browser-support table, typed Ember shim references) where the most important content — "we don't work on this anymore, email a gmail-style obfuscated address if you want the keys" — has been surgically wedged under an H1 called "Development." Lesson: corporate OSS handoffs show their seams at the README's top edge; when the maintenance prose has to live under a heading labeled something else (because restructuring the doc is out of scope for a departing team), the reader can reconstruct the project's lifecycle from the editorial awkwardness alone. The absence of a first-code-snippet — install straight to CDN table — is the second tell: the README assumes you already know what Draggable is, which is what you'd expect of a tool that peaked and then stalled.
