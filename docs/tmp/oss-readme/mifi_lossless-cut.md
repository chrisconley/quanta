# Analysis: mifi/lossless-cut

- **Repo**: mifi/lossless-cut (~39.9k stars)
- **Type**: Cross-platform FFmpeg-backed GUI for lossless video editing
- **Length**: ~12.2 KB

## Sections

1. Centered HTML hero: logo, name, tagline, build badge, donate/release/Discord/Twitter badges, supporter thanks, product screenshot
2. Pitch paragraph
3. Table of Contents (8 links)
4. Features — long bulleted list (40+ items)
5. Example lossless use cases (another long list; very specific use-case scenarios)
6. Download section — store badges (Mac App Store, MS Store, Snapcraft, Flathub), then direct-download links per-OS; donation pitch
7. Supported formats (technical explanation of Chromium HTML5 codec coverage)
8. Documentation links
9. Video demos
10. Featured (press mentions: HN threads by year, Wikipedia, YouTuber mentions)
11. Attributions + "Made with ❤️ in Norway" + author socials

## Tone & style

- **Register**: personal, prosumer-friendly, slightly evangelical about FFmpeg.
- **Voice**: maintainer speaking directly ("me alone," "my supporters"); first person.
- **Formatting**: lots of HTML image badges; frequent inline GitHub issue links (#126, #284, etc.); emoji for emphasis.

## Notable conventions

- Dual "Features" and "Use cases" lists — the first is what the tool *can do*, the second is *why you'd use it*. This separation is unusual and effective for tools with long capability lists.
- Paid store links and free-download links side by side, with explicit framing of why one might pick either.
- "Featured" section doubles as a social-proof trophy case (multiple HN hits across years).
- Attribution to FFmpeg with a "donate to FFmpeg" nudge — ethical vendor-credit.

## Takeaway pattern

An exemplar of a *solo-maintained* consumer OSS project: long, friendly, peppered with personal notes and monetization nudges, but structured well enough to be scannable. The README carries marketing, support, and documentation entry points simultaneously.
